# Agent Flow Trace

Use this skill to make generated agents observable.

## Goal

Agents created by this workbench should include enough trace data to answer:

- which generated agent ran
- which phase started
- which phase ended
- which operation was slow
- which operation appears stuck
- what evidence supports that finding

## Important limitation

Claude cannot automatically intercept every internal model step.

So this skill adds explicit trace entries inside the generated agent instructions.

## What to instrument in generated agents

Add trace points around major phases only:

- discovery
- planning
- broad search
- reading many files
- writing files
- running commands
- verification
- retry or loop
- handoff to another agent

## Trace rule

Each major operation should write:

```text
START <agent>/<phase>/<operation>
END   <agent>/<phase>/<operation>
```

If the run hangs, the likely stuck point is the last `START` without a matching `END`.

## Trace format

Use this format in `.agent-runs/<trace-id>.md` or in the generated agent response if the agent is read-only:

```text
trace_id: <id>
event: START | END | SKIP | ERROR
agent: <agent-name>
phase: <phase-name>
operation: <operation-name>
time: <timestamp or step number>
elapsed_ms: <number or unknown>
evidence: <file, command, tool, or observation>
status: running | success | failed | skipped
```

## Agent instruction block

When adding profiling to a generated agent, include this section:

```markdown
## Profiling and trace logging

For each major phase, record a compact trace entry.

Record `START` before the phase begins.
Record `END` when the phase completes.
Record `ERROR` if the phase fails.
Record `SKIP` if the phase is intentionally skipped.

If the run becomes slow or appears stuck, the last `START` without a matching `END` is the likely stuck operation.

Trace major phases only: discovery, planning, broad search, file read, file write, command run, verification, retry or loop, and handoff.

If exact time is not available, use step order and set `elapsed_ms: unknown`.
```

## Flow

```text
generated agent with trace logging -> agent-flow-profiler analyzes trace if needed
```

## Output

Keep it short:

```text
Result: <tracing added or needed>
Trace points:
- <phase or operation>
Next:
- <how to run or inspect trace>
```

## Rules

- Instrument generated agents, not the workbench itself.
- Do not create noisy logs for every sentence.
- Log workflow phases and expensive operations only.
- Do not claim exact timing when only step order is available.
- Prefer a small trace that can actually be used.
